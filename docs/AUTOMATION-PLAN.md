# Automation plan

Every automation is backend-driven (API service or pg-boss job), writes real records, and is covered by
tests. Status values: **Pending** · **In progress** · **Done (verified)** — "Done" means implemented,
exercised by automated tests, and checked against a running database.

## Idempotency and duplicate-prevention rules
- Posting checks `status = DRAFT` under a row lock (`SELECT … FOR UPDATE`) inside a SERIALIZABLE tx; a second post returns `409 DOC_ALREADY_POSTED`.
- `stock_movements` unique partial index on (`source_type`, `source_id`, `source_line_key`, `is_reversal`) prevents writing the same posting twice.
- Debit note lines unique on (`origin_type`, `origin_id`, `reason`).
- Alerts unique on `dedupe_key` where `status = 'ACTIVE'`.
- Ageing snapshots unique on (`snapshot_date`, `vendor_id`, `bill_id`).
